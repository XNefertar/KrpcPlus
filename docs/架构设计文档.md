## 1. 系统整体架构图与概述

### 1.1 项目概述

Xrpc 是一个基于 C++17 的**高性能分布式 RPC 框架**，面向微服务场景设计，提供远程过程调用的完整基础设施。框架实现了从协议编解码、服务注册发现、负载均衡到全链路可观测的一站式 RPC 能力。

**核心设计目标**：

- 双协议兼容，支撑业务从旧协议到新协议的平滑迁移
- 单端口同时服务多协议客户端，零停机升级
- 10ms 级别端到端延迟，满足低延迟在线服务需求
- 全链路耗时可见，推动性能优化闭环

## 2. 核心组件划分及职责说明

### 2.1 组件总览

| 模块 | 核心类 | 职责 | 依赖 |
|------|--------|------|------|
| **RPC 核心** | `RpcServer`, `RpcChannel`, `Controller` | 服务发布、远程调用、状态跟踪 | Protobuf Service 体系 |
| **编解码层** | `ServerCodec`, `ClientCodec`, `CodecFactory`, `ProtocolMessage` | 双协议编解码、协议自动识别 | protobuf, xrpc_protocol.proto |
| **注册中心** | `ZookeeperClient`, `RouteManager`, `LoadBalancer` | 服务注册/发现、路由缓存、LB | ZooKeeper C API |
| **监控层** | `RuntimeStats`, `ScopedTimer` | 9 阶段耗时统计、分位数计算、瓶颈诊断 | 标准库 (atomic + chrono) |
| **公共层** | `Application`, `Config`, `Logger` | 框架初始化、配置管理、日志 | glog, getopt |

### 2.2 详细组件设计

#### 2.2.1 RpcServer（服务端）

```
RpcServer
├── service_map: unordered_map<service_name, ServiceInfo>
│   └── ServiceInfo { service*, method_map: unordered_map<method_name, MethodDescriptor*> }
├── _serverCodec: unique_ptr<ServerCodec>     ← 首次 OnMessage 时按协议自动创建
├── event_loop: muduo::net::EventLoop          ← 主事件循环
└── NotifyService() / Run() / SendRpcResponse()
```

**生命周期**：

1. 构造时 `event_loop` 创建
2. `NotifyService()` 注册 protobuf Service，遍历 `MethodDescriptor` 填充 `service_map`
3. `Run()` 启动：创建 `TcpServer(address, "RpcServer")`，绑定回调，`setThreadNum(4)`，向 ZK 注册所有服务路径，调用 `event_loop.loop()` 阻塞
4. 每条连接首次 `OnMessage` 时，根据 buffer 前 2 字节 Magic 自动创建对应的 `ServerCodec`（Legacy/XRpc）
5. 业务方法在当前 IO 线程**同步**执行，响应通过 `done->Run()` 回调触发 `SendRpcResponse()`

**OnMessage 处理流程**：

```
buffer → CheckAndPick (粘包处理) → ZeroCopyDecode → 查找 service_map → 反序列化请求
→ service->CallMethod (同步) → done->Run() → ZeroCopyEncode → conn->send()
```

#### 2.2.2 RpcChannel（客户端）

```
RpcChannel : google::protobuf::RpcChannel
├── m_clientfd: int                              ← TCP socket fd
├── _useXrpcProtocol: bool                       ← 协议版本选择
├── _clientCodec: unique_ptr<ClientCodec>        ← 编解码器
└── 两种构造模式:
    ├── RpcChannel(bool connectNow, bool useXrpc)       ZK 模式（延迟连接）
    └── RpcChannel(ip, port, bool useXrpc)              直连模式（跳过 ZK）
```

**CallMethod 9 阶段全链路**：

```
[1] ZK_QUERY       → ZookeeperClient::Start() + QueryServiceHost()
[2] LOAD_BALANCE   → LoadBalancer::Select(routeNodes)
[3] CONNECT        → socket() + connect()
[4] SERIALIZE_REQ  → request->SerializeToString()
[5] ENCODE_REQ     → _clientCodec->ZeroCopyEncode()
[6] NET_IO         → send() + recv_exact()
[7] DECODE_RES     → _clientCodec->ZeroCopyDecode()
[8] DESERIALIZE_RES → response->ParseFromString()
[9] TOTAL          → 整次调用总耗时 (最外层 ScopedTimer)
```

#### 2.2.3 CodecFactory（协议自动识别）

```cpp
// 自动检测逻辑
unique_ptr<ServerCodec> CreateServerCodec(const NoncontiguousBuffer& in) {
    // 读前 2 字节 → 魔数 == 0x4B52 ("KR") ? XRpcCodec : LegacyCodec
}
```

- 服务端首次收到数据时**只检测一次**，之后整个连接生命周期复用同一个 Codec
- 同一端口可同时服务 Legacy 和 XRpc 客户端，各自走各自的 Codec 实例

#### 2.2.4 RouteManager（RCU 无锁路由缓存）

```
RouteManager (单例)
├── _curRouteTable: shared_ptr<const RouteTable>     ← 只读副本（atomic_load）
│   └── RouteTable = unordered_map<path, vector<routeNode>>
├── _writeMutex: mutex                               ← 写写互斥
│
├── GetRouteNodes(path)  → atomic_load + find         O(1) 无锁读
└── UpdateRouteTable(path, zk, watch)                  COW 写
    → lock(_writeMutex) → copy旧表 → 更新 → atomic_store
```

**RCU 模式优势**：

- 读路径：`atomic_load<shared_ptr>` + 普通 map 查找，**零锁开销**
- 写路径：Copy-on-Write 拷贝整表，`atomic_store` 原子替换
- 写写互斥：`_writeMutex` 保证同一时刻只有一个写者

#### 2.2.5 RuntimeStats（监控）

```
RuntimeStats (单例)
├── m_counts[9]: atomic<long long>            ← 每阶段调用次数
├── m_total_times[9]: atomic<long long>       ← 每阶段累计耗时 (纳秒)
├── m_max_times[9]: atomic<long long>         ← 每阶段最大耗时 (CAS 更新)
├── m_hist[9][300]: atomic<long long>         ← 固定桶直方图 (300桶 × 0.1ms = 30ms)
│
├── Record(stage, ms) → 更新 counts + total + max + hist
├── ComputePercentiles(stage) → P50/P95/P99/Avg/Max
└── PrintDetailedReport()
    ├── 分阶段统计表 (Count, Avg, P50, P95, P99, Max)
    ├── 瓶颈分析 (各阶段 P50 占比 + 条形图)
    └── 长尾告警 (P99 / P95 > 3x 触发)
```

**ScopedTimer (RAII)**：构造时记录 start = `high_resolution_clock::now()`，析构时自动 `RuntimeStats::Record(stage, elapsed)`。

## 3. 模块间的交互与数据流向

### 3.1 服务注册流程

```
时间线 ──────────────────────────────────────────────────────────────────►

Callee::Run()
  │
  ├─1─► ZookeeperClient::Start()
  │       └── zookeeper_init(connstr, global_watcher, 6000, this)
  │       └── cv.wait() 阻塞等待 ZOO_CONNECTED_STATE 事件
  │
  ├─2─► for each service::method:
  │       ├── zk.Create("/ServiceName", ...)                    // 服务持久节点
  │       ├── zk.Create("/ServiceName/MethodName", ...)         // 方法持久节点
  │       └── zk.Create("/ServiceName/MethodName/IP:Port",     // 临时节点 (EPHEMERAL)
  │                     data="IP:Port", state=ZOO_EPHEMERAL)    // 断连自动删除
  │
  └─3─► server->start() + event_loop.loop()
          └── 4 个 IO 线程开始 accept 和处理消息
```

### 3.2 服务发现与 RPC 调用流程

```
Caller::CallMethod()
  │
  ├─1─► ZookeeperClient::Start()
  │       └── 连接 ZK，等待 ZOO_CONNECTED_STATE
  │
  ├─2─► QueryServiceHost(service, method)
  │     ├── RouteManager::GetRouteNodes(path)
  │     │     └── atomic_load(&_curRouteTable) → find(path)
  │     │         → 如果有 → 返回缓存
  │     │         → 如果无 → UpdateRouteTable()
  │     │               ├── lock(_writeMutex)
  │     │               ├── zk.GetChildren(path, watch=true)
  │     │               ├── 拷贝旧表 → 更新 → atomic_store
  │     │               └── ZK Watch: 子节点变化时触发 global_watcher
  │     │                     └── ZOO_CHILD_EVENT → UpdateRouteTable() 自动刷新
  │     │
  │     ├─3─► LoadBalancer::Select(routeNodes)
  │     │     ├── RoundRobin: _index.fetch_add(1) % nodes.size()
  │     │     └── Random: thread_local mt19937 + uniform_int_distribution
  │     │
  │     └─4─► 返回 "IP:Port"
  │
  ├─5─► newConnect(ip, port)
  │      └── socket(AF_INET, SOCK_STREAM) → connect()
  │
  ├─6─► request->SerializeToString(&args_str)
  │
  ├─7─► _clientCodec->ZeroCopyEncode(ctx, msg, out)
  │      ├── Legacy: [4B TotalLen][4B HeaderLen][RpcHeader][Body]
  │      └── XRpc:   [16B FixedHeader][RequestProtocol][Body]
  │
  ├─8─► send(m_clientfd, wire_data, ...) + recv_exact()
  │
  ├─9─► _clientCodec->ZeroCopyDecode(ctx, in, resp_msg)
  │
  └─10► response->ParseFromString(resp_msg.body)
```

### 3.3 服务端消息处理流程

```
TcpServer::onMessage(conn, buffer)
  │
  ├─1─► 首次消息: CodecFactory::CreateServerCodec(probe)
  │       ├── Peek(buffer前2B) → magic == 0x4B52 ?
  │       │   ├── Yes → new XRpcServerCodec()
  │       │   └── No  → new LegacyServerCodec()
  │       └── 存入 _serverCodec，当前连接后续复用
  │
  ├─2─► while buffer->readableBytes() > 0:
  │     ├── _serverCodec->CheckAndPick(conn, buf, metadata)
  │     │   ├── 返回 0  → break (半包等待)
  │     │   ├── 返回 <0 → shutdown (非法帧)
  │     │   └── 返回 >0 → 完整帧大小
  │     │
  │     ├── _serverCodec->ZeroCopyDecode(conn, buf, msg)
  │     │   → 填充 ProtocolMessage: service_name, method_name, body, ...
  │     │
  │     ├── buffer->retrieve(frame_size)  // 同步 Muduo Buffer
  │     │
  │     ├── service_map.find(service_name) → method_map.find(method_name)
  │     │
  │     ├── service->GetRequestPrototype(method).New()
  │     │   → request->ParseFromString(msg.body)
  │     │
  │     └── service->CallMethod(method, controller, request, response, done)
  │         └── done->Run() → SendRpcResponse()
  │               ├── response->SerializeToString()
  │               ├── _serverCodec->ZeroCopyEncode(conn, msg, out)
  │               └── conn->send(out.ToString())
  │
  └─3─► 响应发送完成后，当前 IO 线程继续处理下一个消息
```

### 3.4 ZK Watch 自动刷新数据流

```
ZK Event Loop (独立的 watcher 回调线程)
  │
  └── global_watcher(zh, ZOO_CHILD_EVENT, ..., path, watcherCtx)
        │
        └── RouteManager::UpdateRouteTable(path, client, watch=true)
              ├── lock(_writeMutex)
              ├── zk.GetChildren(path, watch=true)   // 重新注册 Watch
              ├── 拷贝旧路由表 → 更新 → atomic_store
              └── 所有 RpcChannel 下次 CallMethod 时自动读到新路由
```

## 4. 技术选型及理由

| 技术组件 | 选型 | 理由 |
|----------|------|------|
| **语言标准** | C++17 | 利用 `shared_ptr` 原子操作 (`atomic_load`/`atomic_store`)、`unordered_map`、结构化绑定等现代特性；配合 Muduo 的 C++ 生态 |
| **网络库（服务端）** | Muduo | 成熟的 Reactor 模型 + 多线程 EventLoop，避免 thread-per-connection 开销；提供 `TcpServer`、`Buffer`、`Timestamp` 等基础设施 |
| **网络（客户端）** | 原生 socket | 客户端使用 raw socket (`send`/`recv`)，轻量无依赖，`xrpc_core` 库不链接 Muduo |
| **序列化** | Protobuf | 语言无关、高效的二进制序列化；`cc_generic_services=true` 直接生成 Stub/Skeleton，无缝对接 RPC 框架 |
| **服务注册与发现** | ZooKeeper | C++ RPC 生态事实标准（brpc、tars 均使用），官方 C 客户端 `libzookeeper_mt` 久经考验；临时节点（EPHEMERAL）无需应用层心跳即可自动摘除故障节点；Watch 机制实现路由实时更新。配合 RCU 缓存后 ZK 仅在 cache miss 和节点变更时访问，不在 RPC 热路径上，因此 ZK 的性能特性不影响整体吞吐。选型上也考虑了 etcd，但其 C++ 客户端为社区维护、成熟度不足，且 Lease + KeepAlive 机制比 EPHEMERAL 更复杂 |
| **负载均衡** | 自研（RoundRobin + Random） | 轻量实现，`atomic fetch_add` 无锁轮询，`thread_local mt19937` 避免锁竞争 |
| **路由缓存** | RCU (Read-Copy-Update) | `atomic_load<shared_ptr>` 零锁读，COW 写 + `atomic_store`，最小化读路径延迟 |
| **日志** | Glog | Google 内部验证的 C++ 日志库；在 macOS 上使用 stub 替代，降低平台依赖性 |
| **配置管理** | 自定义 Config (key=value 文件) | 极简实现：`unordered_map` + 文件行解析 + `getopt` 命令行覆盖，无外部依赖 |
| **监控统计** | 自研（固定桶直方图） | 纯 C++17 标准库实现，无 Prometheus 依赖；300 桶 × 0.1ms 覆盖 0-30ms 范围 |

**客户端/服务端库分离设计**：

```
xrpc_core (STATIC)           xrpc_server_core (STATIC)
├── codec/                    ├── rpc/server.cc
├── common/                   └── 依赖: xrpc_core + muduo_net + muduo_base
├── monitor/
├── protocol/
├── registry/
├── rpc/channel.cc
└── 依赖: protobuf (无 Muduo)
```

- 客户端只链接 `xrpc_core`（无 Muduo 依赖），更轻量
- 服务端额外链接 `xrpc_server_core`（含 Muduo）

## 5. 数据库表结构或存储设计

Xrpc 不使用传统关系型数据库，其"存储"主要分为三类：

### 5.1 ZooKeeper 节点树

```
/
├── UserService/                          ← 持久节点 (PERSISTENT)
│   ├── Login/                            ← 持久节点
│   │   ├── 192.168.1.10:8000            ← 临时节点 (EPHEMERAL), data="192.168.1.10:8000"
│   │   ├── 192.168.1.11:8000            ← 临时节点
│   │   └── 192.168.1.12:8000            ← 临时节点
│   └── Register/                         ← 持久节点
│       ├── 192.168.1.10:8000            ← 临时节点
│       └── 192.168.1.11:8000            ← 临时节点
└── OrderService/
    └── CreateOrder/
        └── 192.168.2.1:8000             ← 临时节点
```

**节点属性**：

| 路径 | 类型 | 内容 | 说明 |
|------|------|------|------|
| `/{ServiceName}` | 持久节点 | — | 服务根路径 |
| `/{ServiceName}/{MethodName}` | 持久节点 | — | 方法路径 |
| `/{ServiceName}/{MethodName}/{IP:Port}` | **临时节点** (EPHEMERAL) | `IP:Port` | 实例地址，服务下线自动删除 |

**设计要点**：

- 临时节点保障故障自动摘除：服务端进程退出/网络断开时，ZK session 超时后自动清理
- 客户端监听 `ZOO_CHILD_EVENT`，节点变化时自动触发 `RouteManager::UpdateRouteTable()`

### 5.2 内存路由表（RCU 缓存）

```
RouteTable (unordered_map)
┌──────────────────────────────────────┬─────────────────────────────────────┐
│ Key (path)                           │ Value (routeNodes)                  │
├──────────────────────────────────────┼─────────────────────────────────────┤
│ "/UserService/Login"                 │ ["192.168.1.10:8000",              │
│                                      │  "192.168.1.11:8000",              │
│                                      │  "192.168.1.12:8000"]             │
├──────────────────────────────────────┼─────────────────────────────────────┤
│ "/UserService/Register"              │ ["192.168.1.10:8000",              │
│                                      │  "192.168.1.11:8000"]             │
└──────────────────────────────────────┴─────────────────────────────────────┘
```

**访问模式**：

- 写：`UpdateRouteTable()` → `lock(_writeMutex)` → 拷贝整表 → 更新目标 key → `atomic_store`
- 读：`GetRouteNodes()` → `atomic_load` → `find(key)` → 返回副本

#### ServerCodec

```cpp
class ServerCodec {
public:
```

## 7. 非功能性设计

### 7.1 高可用

**服务端高可用**：

| 机制 | 实现 | 效果 |
|------|------|------|
| 临时节点 | `zoo_create(..., ZOO_EPHEMERAL)` | 进程退出/ZK session 超时后自动摘除 |
| ZK Watch 自动刷新 | `global_watcher` 监听 `ZOO_CHILD_EVENT` | 节点上下线秒级感知，路由表自动更新 |
| 多实例部署 | 同方法下注册多个 `IP:Port` 临时节点 | 无单点故障 |

**客户端容错**：

| 机制 | 实现 | 说明 |
|------|------|------|
| 重试连接 | `newConnect()` 失败时最多重试 3 次 | `while (!rt && count--) { rt = newConnect(...); }` |
| 错误传播 | `controller->SetFailed("...")` + `controller->Failed()` | 业务方可检查并处理 |
| Socket 异常恢复 | `recv` 返回 0 / -1 时 `close(fd)` 并设 `m_clientfd = -1` | 下次调用重新建连 |

### 7.2 扩展性

| 设计点 | 扩展方式 |
|--------|----------|
| **新增协议** | 实现 `ServerCodec` / `ClientCodec` 接口，在 `CodecFactory` 注册新的 Magic Number |
| **新增负载均衡策略** | 继承 `LoadBalancer` 抽象基类，实现 `Select()` 方法 |
| **新增序列化格式** | `ContentType` 枚举已预留 `kJson`、`kFlatBuffers`，Codec 层可切换 |
| **新增压缩算法** | `ContentEncoding` 枚举已预留 `kGzip`、`kSnappy`、`kLZ4` |
| **替换注册中心** | `RouteManager` 接口不变，替换 `ZookeeperClient` 实现即可（如 etcd/consul） |
| **新增流式调用** | `StreamType` 枚举已预留 `kClientStream` / `kServerStream` / `kBidiStream` |
| **新增监控后端** | `RuntimeStats::Record()` 可扩展为同时写 Prometheus/InfluxDB |

**库拆分架构支持**：

- `xrpc_core`（客户端）：仅依赖 protobuf，无 Muduo，可嵌入到任何 C++ 应用中
- `xrpc_server_core`（服务端）：额外依赖 Muduo，职责清晰

### 7.3 安全性

| 安全措施 | 实现 |
|----------|------|
| **帧大小上限** | `kMaxFrameSize = 16MB`，`CheckAndPick` 中检测超大帧，返回 `kCodecOversized` 并断开连接 |
| **魔数校验** | XRpc 协议 `FixedHeader::IsValid()` 校验 magic `0x4B52`，不匹配返回 `kCodecInvalidMagic` |
| **长度一致性** | 验证 `header_size <= total_size - kFixedHeaderSize`，防止越界读取 |
| **半包防护** | `CheckAndPick` 返回 0 时等待更多数据，不会提前部分解码导致状态错乱 |
| **非法帧断开** | `CheckAndPick` 返回 <0 时立即 `conn->shutdown()`，不泄露连接资源 |
| **ZK 安全** | 默认 `ZOO_OPEN_ACL_UNSAFE`（开发模式），生产环境应配置 `digest` 认证 |

### 7.4 性能保障

#### 7.4.1 服务端优化

| 优化点 | 实现 |
|--------|------|
| **多 Reactor 模型** | `TcpServer::setThreadNum(4)`，4 个 EventLoop 线程分摊连接和 I/O |
| **零拷贝编解码** | `NoncontiguousBuffer` 链式存储 + `Peek/Skip` 模式，不拷贝 buffer 内容给 Codec |
| **协议仅检测一次** | Codec 在连接首次消息时创建，后续消息直接使用，无重复检测开销 |
| **粘包批量处理** | `while (buffer->readableBytes() > 0)` 循环处理粘包，单次 `OnMessage` 可处理多个完整帧 |

#### 7.4.2 客户端优化

| 优化点 | 实现 |
|--------|------|
| **RCU 无锁路由查找** | `atomic_load<shared_ptr>` 零锁读取路由表 |
| **RoundRobin 无锁轮询** | `atomic<size_t>::fetch_add(1)` 无锁递增 |
| **Random LB 线程隔离** | `thread_local mt19937` 避免锁竞争 |
| **recv_exact 循环读取** | 处理 TCP 拆包，避免 `recv` 未读满时的错误处理 |
| **连接复用** | `m_clientfd` 保持连接，一次 `CallMethod` 后不关闭 |
| **命令行动态覆盖** | `-a <ip>` / `-p <port>` 可运行时覆盖配置，无需重新编译 |

#### 7.4.3 内存与分配

| 优化点 | 实现 |
|--------|------|
| **ProtocolMessage 复用** | `msg.Reset()` 重置后重用，减少堆分配 |
| **预分配 buffer** | `recv_exact` 中使用 `resize()` 预分配目标大小 |
| **NoncontiguousBuffer 链式存储** | `deque<Block>` 追加不拷贝旧数据 |
